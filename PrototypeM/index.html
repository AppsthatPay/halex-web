AI Sockets

The hardwired principle: the app and its libraries are fixed, immutable software. The AI is the electrician, not the architect — it wires components together and operates them, and can never modify, add to, or destroy the code.

The socket rule

Read-only on code, execute-only on operations. An AI connected through a socket receives structured capabilities — quote, scan, prepare, publish — and returns structured results. Anything an AI produces for a public surface passes the halex-security gates before it ships. That's how the RUSTY page-design channel works: design tokens in, verified page out.

Security — halex-security

Two gates stand between any writer and the Braintree knowledgebase. Nothing reaches a tag except through braintree.propose().

UXSS gate PASSING

Blocks script tags, javascript: URIs and event handlers in anything destined for the HALEX UI. Protects every rendered surface, including AI-designed token pages.

SHELL gate PASSING

Blocks shell/code injection and prompt injection aimed at the machine or the AI. Dirty proposals go to quarantine — they never touch a tag.

Write path

propose() → UXSS gate → SHELL gate → appended as next R-observation, with provenance

Tag lifecycle: Seed → Feed → Verify → Prune → Forge. Direct tag edits that bypass propose() are a violation. Security layers sit entirely outside BCIA command — the council gets sanitized status only, never raw internals, and cannot weaken a gate.
